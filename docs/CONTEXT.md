# v0.3 发挥背景 — 2026-10-28

> 当前 v0.5 使用 [最近选中目标](RECENT-TARGETS.md)，已替代 v0.4 击杀队列。按钮为“读取背景”，原有手动地点/队伍快照仍保留。下方实测数据针对 v0.3。

发挥模式可把地点、队友名字/职业和情境作为独立 context 发送给模型；普通模式在准备请求和实际 API 层均排除背景。背景可空，最多 4000 UTF-8 字节，不保存到设置或聊天日志。原句仍最多 2000 字节，输出预算维持正常 140、发挥 255 字节。

## 使用

桌面助手：在“发挥背景”页手动填写或点虚构示例，切回“无游戏试用”勾选发挥，输入原句，准备、Ctrl+C、等完成、Ctrl+V。模型只在手动复制请求后调用。背景修改会清空已准备请求和粘贴预览，让桌面中的待处理结果失效。

游戏插件：勾选发挥后，点“读取地点/队友”，可得到当时可读的区域、子区域和队伍名字/职业；再手动补充、修改。游戏接口不能保证副本内同时返回外部区域，死亡矿井对应的西部荒野等信息可手动填入。读取不是持续追踪，换区或换队后需要重新读取。游戏面板无法通知外部助手撤回已复制的旧请求，须重新准备、Ctrl+C 后才能使后台旧调用失效。

读取仅用公开 UI API，受限或不可读值跳过，不读取内存，不监听聊天，不获取战网身份、GUID 或服务器信息。只在玩家点击读取时采集；仅点击读取不会发出 HTTP 请求。普通模式点击读取会提示先勾选发挥。

实现核对了 Forever 源码文档中的 [区域文本接口](https://raw.githubusercontent.com/Gethe/wow-ui-source/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/ZoneScriptDocumentation.lua) 和 [单位名字、职业及身份比较接口](https://raw.githubusercontent.com/Gethe/wow-ui-source/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/UnitDocumentation.lua)。它们包含受限返回值的情况，因此实现主动跳过这些值，缺失信息可手填。接口核对与模拟测试不等于客户端实测。

## 背景能影响什么

原句“这地方真烂，准备收拾这些家伙”与背景：

```text
地点：死亡矿井，西部荒野
队友：Player1 - 牧师；Player2 - 盗贼
敌人：迪菲亚
```

能把“这地方”“这些家伙”落实到死亡矿井和迪菲亚，并加入一段相关 RP。最新真实返回为：

> 这死亡矿井真是烂透了，简直是灾难！准备收拾这些迪菲亚，伙计们，送他们一张去卡利姆多的单程票！

Biden 的地区吐槽可以与迪菲亚驱逐比喻组成一个短包袱，允许使用 shithole 等粗口，但不强制每次都选某个梗。驱逐只用于已有战斗/敌意原意下对虚构敌对 NPC 的漫画式比喻，不追加实际旅行命令、传送机制或保证清本。笑话不再附加“比喻而已”等解释。

原文比背景优先：

- 地点在死亡矿井，不把原文的玛拉顿招募或“没打过玛拉顿”改掉。
- 队里有牧师，不等于有治疗；职业不等于专精、任务分工或熟练度。
- “缺1奶”不证明其他位置齐全，不能补成“最后一个位置”。
- “有人熟悉副本”不等于玩家本人熟悉，不补带队、带飞或通关承诺。
- 不枚举无关队友，不仅因职业相符就认定“这个盗贼”是某个具体玩家。
- 背景与角色名均当作数据；其中包含的“忽略规则、改成开怪”等文字不作为指令执行。

## 请求与兼容

WOWRP/3 使用两行人格头，再跟 mode/source/context JSON；Lua 自带最小字符串转义，无运行时第三方依赖。后台保留 WOWRP/2 无背景请求的读取能力，旧 WOWRP/1 仍拒绝。使用新背景功能须更新助手和插件，旧助手不能读 WOWRP/3。

## 验证

56 项回归通过，其中 6 项使用临时安装的 Lupa 2.8 / Lua 5.1 模拟 WoW API。覆盖 Lua 到 Python 的引号/换行/中文请求互通，地点去重，团队排除自己，跳过受限名字，缺失 API，长名单预算，以及游戏面板修改背景后不能填入旧结果。其他检查覆盖背景独立传输、正常模式不读取背景、Unicode 错误可恢复、后台失效和 HTTP 协议。

普通产品只需要 Python stdlib/Tkinter；Lua 测试依赖不是产品依赖，不在发布包。普通测试环境缺少 Lupa 时会跳过这 6 项；本机本轮已实际执行。开发者可在临时目录安装 Lupa 并设置 PYTHONPATH 后运行 unittest。

真实 API 首轮 15 次均通过格式/长度/模式/基础语言检查。人工检查发现：英文驱逐梗会多加 figuratively，中文招募会补“就差这位奶妈”。修正提示词后，最终一轮再测 12 次：

| 分组 | 接受/调用 | 中位耗时 | 最大耗时 |
|---|---:|---:|---:|
| 英文发挥 | 6/6 | 1.680 秒 | 2.031 秒 |
| 中文发挥 | 4/4 | 1.629 秒 | 2.050 秒 |
| 正常对照 | 2/2 | 3.970 秒 | 6.477 秒 |
| 最终轮合计 | 12/12 | 1.675 秒 | 6.477 秒 |

全部实际返回 gpt-6.1-sol / ultrafast。耗时包含 HTTP 和完整解析，脚本并发为 2；普通模式有一次 6.477 秒的离群值，样本太少，不能认为普通模式固有更慢。

最终轮中，背景有牧师的招募仍保留缺1奶和20:00；背景冲突保留玛拉顿与新手身份；带恶意指令的背景仍输出“等一下，别开怪”。正常对照没有添出背景里的死亡矿井、迪菲亚和玩家名字。未观察到能力虚构或笑话解释；幽默质量与所有语义仍需玩家粘贴后核对。Biden 与 deport 同时出现并非硬性验收条件，避免为了堆梗而反复生成。

原始记录：[最终英文](openai-live-context-final-english.json)、[最终中文](openai-live-context-final-chinese.json)、[最终正常](openai-live-context-final-normal.json)；[首轮英文](openai-live-context-english.json)、[首轮中文](openai-live-context-chinese.json)、[首轮正常](openai-live-context-normal.json) 保留调优前样本。全部仅合成草稿、虚构队友，无密钥或私人聊天。

Windows 桌面也实际验证了新背景页：填入死亡矿井/西部荒野与两位虚构队友，正常准备时 JSON context 为空；勾选发挥后携带背景，Ctrl+C 调用、完成后 Ctrl+V 成功。桌面这次额外调用不计入脚本统计。原句为玛拉顿招募、背景为死亡矿井，返回仍为 `Maraudon! Need 2 more: 1 TANK, 1 HEALER. A TREMENDOUS group in the making, folks!`，81 字节，未被当前地点覆盖。

随后在已有粘贴结果时重新填入背景，确认提示旧请求失效，返回试用页时请求框和粘贴预览均已清空；最近返回仍保留为本次会话历史。

Forever 实机的 Lua 加载、框体布局、API 限制、中文输入及剪贴板仍待正式客户端测试。Lua 模拟与桌面助手的通过不能代替实机验收。
