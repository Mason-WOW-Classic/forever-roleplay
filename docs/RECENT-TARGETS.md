# v0.5 最近选中目标背景 — 2026-10-28

用最近选中过的非玩家目标名字提供场景素材，完全替换 v0.4 的击杀确认方案。保留地点、队友和手动补充背景；模型仍为 Sol Ultrafast，默认正常、手动勾选发挥、复制触发、玩家手动发送。

## 如何读取

监听玩家的 PLAYER_TARGET_CHANGED，用 UnitExists("target") 判断目标存在，UnitIsPlayer("target") 明确返回 false 时才读取 UnitName("target")。只读普通公开接口，不选择、切换或清除目标，不读取战斗日志、GUID、血量或击杀归属。没有选中目标、身份不明、名字受限/无效或接口错误时跳过，保留已有名单。

这些事件和函数已在 Forever 的 [Unit 接口声明](https://raw.githubusercontent.com/Gethe/wow-ui-source/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/UnitDocumentation.lua) 中核对，避免了旧方案的战斗日志读取函数缺失问题。目标名字仍可能受身份限制，不能保证任何状态下都可读；实际客户端仍需验证。

## 列表规则

- 只存名字，最多 10 个不同名字，最近选中的排最前。
- 重选同名目标时移到最前；即使是不同个体，只要名字相同也合并。
- 超过 10 个时移出最久未选中的名字，返回给其他模块的列表是副本。
- 友方商人、训练师、任务 NPC、宠物等，只要明确不是玩家，都能提供场景信息；不推断敌意或是否活着。
- 同一区域取消目标、选中玩家或遇到不可读目标时，不清空已有名单。
- 主区域变化、进入/离开副本或重新载入世界时清空；同一区域内换房间不清空。读取背景和新目标事件还会核对主区域，补漏掉的区域事件。
- 只在内存中维护，关闭游戏或重新加载后不保留。选择目标不会联网，不调用 LLM。

例：选中“迪菲亚矿工 → 迪菲亚监工 → 迪菲亚矿工”，名单为：

```text
最近选中过的非玩家目标（仅作场景背景）：迪菲亚矿工；迪菲亚监工
```

模型可据此选用与迪菲亚相关的包袱，但不能说玩家已击杀它们、当前正攻击它们、已经清本或熟悉副本。名单不是当前目标，也不证明所有名字都是敌人；战斗意图和招募条件仍由原句决定。原有话题边界继续适用。

## 背景与区域更新

“读取背景”按钮显示当前地点、队友和最近目标。每次准备发挥请求时，都会把最新目标名单合并进背景，替换旧自动名单；也清理旧版自动生成的击杀背景行。正常模式不附带名单或其他背景。

换区时清空名单、请求和粘贴预览；未编辑的整份自动快照清空，手动补充的其他文字保留，仅移除自动名单行。游戏插件无法撤销外部助手已发出的旧调用，换区后须重新准备、Ctrl+C，并检查粘贴内容。

## 验证

72 项回归通过，其中 20 项使用 Lua 5.1 模拟。覆盖事件触发、玩家/空目标/不明身份过滤、受限值与 API 错误、中文名字、10 个不同名字的容量、重选移到最前、友方目标、主区域重置与房间保留、背景合并和旧击杀行清理。游戏 UI 模拟验证：读取背景后再选新目标，准备时能加入最新名单；换区后旧请求与自动快照清空。
